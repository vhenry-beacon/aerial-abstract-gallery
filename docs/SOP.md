# Aerial Abstract: Client Gallery SOP

How to deliver a shoot through a private client gallery, from footage to payment. Each step names the file or command used. Follow it in order for every new client.

---

## How the system works

- **One website, many galleries.** The site is `aerial-abstract-gallery.netlify.app`, and each client gets a private gallery at `/g/<client-slug>`, protected by an access code.
- **Previews are public-safe.** The client browses watermarked, reduced-size previews.
- **Full-quality files are private.** They are stored in a Cloudflare R2 bucket (or Netlify Blobs if R2 isn't configured). Clients get a 10-minute download link only for items they've picked within their package or paid for.
- **Pricing is in each client's config file.** That covers the package price, how many deliverables are included, the price per extra, and add-ons. Nothing is hardcoded.
- **Stripe handles payment.** The site calculates the total on the server, sends the client to Stripe Checkout, and unlocks the files when payment succeeds.
- **The admin page** (`/admin`) is where Keri uploads full-quality files, sees orders, and marks offline payments (PayPal, Zelle, check).

## Folder layout (project)

```
aerial-abstract-gallery/
  clients/<slug>/client.json     ← one per client: name, pricing, access code hash, add-ons
  clients/<slug>/manifest.json   ← list of clips/photos (generated by the tools)
  public/media/<slug>/           ← watermarked previews (generated)
  tools/process_photos.py        ← HEIC→JPEG, auto-enhance, previews
  tools/process_clips.py         ← split long video into scene clips + previews
  tools/make_reel.py             ← ~30s highlight reel with title (+ music)
  tools/build_manifest.py        ← writes manifest.json
  netlify/functions/api.mts      ← gallery, cart, checkout, admin API
  netlify/edge-functions/download.ts ← gated full-res downloads
  docs/SOP.md                    ← this file
```

## Step by step for a new client

### 1. After the shoot: organize the files
On the USB or drive, make one folder per client with two subfolders:
- `Photos-Unedited/`: all stills (drone JPEG, Osmo JPEG, phone HEIC are all fine)
- `Videos-Vertical/` (and/or `Videos-Landscape/`): the edited Premiere export(s)

Export the vertical edit from Premiere as one long H.264 MP4 with **hard cuts between scenes**. The clip splitter finds those cuts automatically. Audio is optional.

### 2. Create the client config
Copy `clients/river-oaks/` to `clients/<new-slug>/` (lowercase, dashes, for example `lakeside-cc-open`). Edit `client.json`:

| Field | Meaning |
|---|---|
| `slug` | Must match the folder name. It becomes the URL `/g/<slug>`. |
| `clientName`, `eventName`, `eventDate` | Shown on the gallery. |
| `contactEmail` | Prefills the Stripe receipt email. |
| `accessCodeHash` | SHA-256 of the access code in UPPERCASE. Make one with: `printf %s "CODE-1234" \| shasum -a 256` |
| `package.name / price / included` | Price is in **cents** (65000 = $650). `included` = deliverables in the package. |
| `package.paidOffline` | `true` if they already paid you outside the site. |
| `extraPrice` | Per extra deliverable in cents (2500 = $25). |
| `upsells` | Add-ons such as the highlight reel (price in cents). Remove the block if not offered. |

Delete the copied `manifest.json`. The tools regenerate it.

### 3. Process the photos
```
python3 tools/process_photos.py --src "<client>/Photos-Unedited" \
   --full work/<slug>/full --preview public/media/<slug> > work/<slug>/photos.json
```
- Converts HEIC to JPEG, applies a gentle auto-enhance, and orders aerials first.
- Full-quality files land in `work/<slug>/full/` as `photo-01.jpg`, `photo-02.jpg`, and so on.
- Add `--no-enhance` to deliver the photos untouched.

### 4. Cut the video into clips
```
python3 tools/process_clips.py --src "<client>/Videos-Vertical/edit.mp4" \
   --full work/<slug>/full --preview public/media/<slug> --min 0 --max 999 > work/<slug>/clips.json
```
- `--min 0 --max 999` = **one clip per scene** (what we used for River Oaks).
- `--min 10 --max 15` = merge short scenes and split long ones to land at 10–15s each.
- Add `--plan-only` first to preview the cut list without rendering.
- For a landscape edit, run again with `--src` set to the landscape file, `--prefix wide`, and `--start-index 1`, writing to `wide.json`. Then append its items to `clips.json`.

**Rule of thumb:** the edit's length caps the clip count. 80 seconds gives about 11 scene clips. For 25+ clips, export a longer selects reel from Premiere (3–5 minutes of best moments, hard cuts between shots).

### 5. (Optional) Make the sample highlight reel
```
python3 tools/make_reel.py --src edit.mp4 \
  --moments "1.0:4.6,47.8:3.5,52.5:3.5,..." \
  --title "Fall Festival" --subtitle "River Oaks Islamic Center" --endcard "October 31, 2026" \
  --music licensed-track.mp3 \
  --out work/<slug>/reel/highlight-reel.mp4 --preview public/media/<slug>/reel-sample.mp4
```
`--moments` = `start:seconds` pairs from the source, about 9 of them for 30s. **Only use music Keri holds a license for** (for example, a paid Artlist or Epidemic Sound track, or the YouTube Audio Library / Pixabay free licenses). Keep the license receipt with the job.

### 6. Build the manifest
```
python3 tools/build_manifest.py --slug <slug> --work work/<slug>
```

### 7. Publish the site
Commit the new `clients/<slug>/` folder and its `public/media/<slug>/` previews to GitHub (or ask Claude to). Netlify publishes automatically within about 2 minutes.

### 8. Upload the full-quality files
1. Open `https://aerial-abstract-gallery.netlify.app/admin` and sign in.
2. Choose the client and drag everything from `work/<slug>/full/` onto the drop zone. Files split for transport (`.001`, `.002`, …) can be dropped together, and they're rejoined automatically.
3. Every row in **Items** should say *uploaded*. Use **Test download** on one clip.

### 0. Keri starts a project (admin home)
`/admin/` shows a tile per project (cover, client, date, status: Quote → Files uploaded → With Claude → Keri reviewing → Published → Paid). **+ New project** asks for a name, client and date, then opens the project page:
- **Quote:** client contact, event, package name and price, deliverables included, price per extra, add-ons, due date, and the full quote details. These numbers become the gallery's pricing.
- **Instructions for Claude:** how to edit (look, clip length, must-have shots, reel style).
- **Files:** drop the whole shoot; it uploads straight to R2 at `raw/<project-id>/`, folders kept, resumable.
- **Send to Claude**, with an optional note. The project moves to *With Claude*.

Claude then builds the gallery:
```
.venv/bin/python tools/project.py list                      # what's been sent
.venv/bin/python tools/project.py show --id <id>            # quote, instructions, note, file list
.venv/bin/python tools/project.py fetch --id <id> --to <scratch dir>   # raw files (delete after)
# process_photos.py / process_clips.py into work/<slug>/ (steps 3-5 below)
.venv/bin/python tools/project.py scaffold --id <id> [--slug S]  # client.json from the quote + new access code (stored on the project, not printed)
python3 tools/build_manifest.py --slug <slug> --work work/<slug>
.venv/bin/python tools/project.py upload-full --slug <slug> --dir work/<slug>/full
netlify deploy --prod --build
.venv/bin/python tools/project.py link --id <id> --slug <slug>   # gallery link + access code appear on the project page
```
Only a reel add-on becomes a gallery add-on automatically; other add-ons are handled by hand.

### 8b. Keri reviews everything in the studio, then publishes
Every new gallery starts **unpublished**: the access code works, but the client sees "Your gallery is being finished" until Keri publishes it. Once published, the client sees **only items Keri approved** (plus anything they already own).

Keri opens `/admin/studio/` (or **Review studio** on the admin page):
- **Photos & clips:** for each item, **Approve**, **Needs edits** or **Remove**. To ask for changes she can pick a **look** (Bright & clean, Warm golden, Cool blue, Vivid, Cinematic, Soft matte, Black & white, Vintage, plus fine-tune sliders), a **speed** (0.25× to 4×), a **trim** (start and end), and leave **notes**, optionally pinned to a moment in the clip. The preview shows the look and speed live (an approximation), then she clicks **Save edit request**.
- **Highlight reel:** the reel is a row of pieces (clip + start + end). She can drag pieces to reorder them, change each piece's start/end, speed and look, add or remove pieces, and set the title, subtitle, closing text, transitions, overall look and music. **Play reel** previews it in order.
- **Upload files:** drop a whole shoot (files or folders, raw and edited) and it uploads straight to R2 under `raw/<project>/`, in 16 MB parts, 3 files at a time. Interrupted? Drop the same files again and it resumes. Files already there are skipped. Everything uploaded is listed with a download link.
- **Publish gallery** (top right) when she's happy. **Preview as client** shows exactly what the client will see.

**Edit queued / Note for Claude.** Saving a look, speed or trim marks the item *⏳ Edit queued*; the **auto-editor** (below) renders it within about 15 minutes while Vernon's Mac is on, and it comes back *Updated, check it*. A written note marks it *💬 Note for Claude*: those need Claude's judgment, so Keri tells Vernon (or Claude) "Keri left notes". The banner at the top of the studio shows both, and when the auto-editor last checked in.

**Auto-editor:** `tools/autorender.sh` → `studio.py auto`, every 15 minutes via the LaunchAgent `com.aerialabstract.autorender` (install with `bash tools/install_autorender.sh`, remove with `--remove`; log in `~/Library/Logs/aerial-abstract-autorender.log`). Each round: render every gallery's queued requests, deploy, make a local git commit (pushing happens in a normal session), and report to the site. Its notes are signed "Auto-editor", so they don't count as answering Keri's written notes.

Claude handles notes (and can render by hand):
```
.venv/bin/python tools/studio.py status --slug <slug>     # read Keri's notes and edit requests
.venv/bin/python tools/studio.py set --slug <slug> --id clip-03 --trim 0.8:3.0   # turn a note into an exact edit
.venv/bin/python tools/studio.py render --slug <slug>    # render every changed request (or --ids clip-03,photo-02)
.venv/bin/python tools/studio.py render --slug <slug> --reel [--music licensed-track.mp3]
.venv/bin/python tools/studio.py reply --slug <slug> --id clip-03 --text "..."   # answer a note (--id reel for the reel)
npm run build && netlify deploy --prod --build            # previews and manifest changed: publish and commit
```
- Edits always start from the **untouched original**, kept at `orig/<slug>/<id>` in R2 (copied from `full/` the first time an item is edited). Clearing an edit copies the original back byte for byte.
- Each render uploads the new full-quality file, regenerates the watermarked preview (with a `?v=` cache-buster), and marks the item **Updated, check it** with a note from Claude saying what changed. Keri approves it or leaves another note.
- Slow motion is smoothed with motion interpolation: about 25 seconds of work per second of 4K output on the M1 Max. The reel renders in about a minute.
- The full-quality reel is uploaded to the gallery **only when `--music` is given** (a licensed track). Without music, only the preview is updated.
- One-time setup on a new Mac: `python3 -m venv .venv && .venv/bin/pip install pillow numpy pillow-heif` (ffmpeg via Homebrew).

### 9. Send the client their link
Email the client:
> Your Fall Festival gallery is ready: https://aerial-abstract-gallery.netlify.app/g/<slug>
> Access code: **XXXX-XXXX**
> Pick the 15 photos/clips included in your package; extras are $25 each. Your full-quality files unlock as soon as checkout is complete.

### 10. Get paid and deliver
- **Card payment:** happens automatically. The order shows under **Orders** in admin, and the files unlock for the client right away.
- **PayPal, Zelle or check:** after the money arrives, open admin and click **Mark the client's current cart as paid**.
- **Reel purchased:** finish the reel with music, then upload `highlight-reel.mp4` in admin. It appears under the client's **My files**.
- **Freebie or courtesy file:** use **Give free** on that item.

## One-time setup (already done for the site, listed here for reference)

| Setting (Netlify → Site configuration → Environment variables) | Purpose |
|---|---|
| `SESSION_SECRET` | Signs client and admin sessions. Long random string. Set. |
| `ADMIN_PASSWORD` | Keri's admin sign-in. Set. Change any time, then redeploy. |
| `STRIPE_SECRET_KEY` | Keri's Stripe key (`sk_test_…` while testing, `sk_live_…` when live). **Keri adds this herself.** |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` | Cloudflare R2 storage for full-quality files. From Cloudflare → R2 → Manage API tokens (Object Read & Write, scoped to the bucket). Paste them here, never in chat. |
| `STRIPE_WEBHOOK_SECRET` | Optional backup confirmation. Stripe → Developers → Webhooks → add endpoint `https://aerial-abstract-gallery.netlify.app/api/stripe-webhook`, event `checkout.session.completed`, then copy the signing secret here. |

**R2 bucket CORS** (Cloudflare → R2 → bucket → Settings → CORS policy). This lets the admin page upload straight from the browser:
```json
[{"AllowedOrigins":["https://aerial-abstract-gallery.netlify.app"],"AllowedMethods":["PUT","GET","HEAD"],"AllowedHeaders":["content-type"],"MaxAgeSeconds":3600}]
```

**Code and deploys:** the code lives in GitHub (`vhenry-beacon/aerial-abstract-gallery`). Netlify is linked to it, so every push to `main` publishes automatically. Ask Claude to make a change, and Claude pushes it.

**Visitor access:** in Netlify → Site configuration → Access & security → Visitor access, production must **not** require Netlify team login, or clients can't open their gallery.

**Testing payments:** with a `sk_test_` key, pay with card `4242 4242 4242 4242`, any future date, any CVC. Switch to the `sk_live_` key and redeploy to take real payments.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Client sees "Online payment isn't switched on yet" | `STRIPE_SECRET_KEY` is missing. Add it and redeploy. |
| A purchased file shows "Preparing…" | Its full-quality file hasn't been uploaded. Upload it in admin. |
| Client paid but files are still locked | In admin, check **Orders**. If Stripe shows the payment, use **Give free** on those items and check the webhook setup. |
| An upload fails partway | Drop the same file again. It overwrites cleanly. |
| A new client doesn't appear | Its `clients/<slug>/client.json` slug must match the folder name. Redeploy. |
